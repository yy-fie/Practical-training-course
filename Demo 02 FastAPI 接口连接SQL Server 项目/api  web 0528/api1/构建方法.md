# FastAPI 为 SQL Server 数据库构建接口项目 —— 构建方法

> 本文档总结本项目从「一张 SQL Server 数据表」到「一套可用的 FastAPI 接口」的完整构建方法，作为后续为新表（例如 `FloorInfo`、`RoomInfo`、`StudentInfo` 等）生成接口的模板与规范。

## 1. 项目技术栈与运行环境

- 后端框架：FastAPI（`fastapi==0.104.1` 及以上均可）
- Web 服务器：Uvicorn（`uvicorn.run(app, host="127.0.0.1", port=9001)`）
- 数据访问：pyodbc（连接 SQL Server）
- 数据库：Microsoft SQL Server（本项目使用 Windows 可信连接）
- 数据校验/序列化：Pydantic v2（`pydantic==2.5.0` 及以上）

> 注意：本项目源码中大量使用 `List[Model]` 类型注解。若运行环境是 Python 3.9 以下（例如 Python 3.8），必须使用 `from typing import List` 并写成 `List[...]`，不能直接写 `list[...]`，否则导入时会报 `TypeError: 'type' object is not subscriptable`。

## 3. 数据库连接（database.py）

核心是提供一个统一的连接函数，所有接口通过它获取连接：

```python
import pyodbc

SERVER = '.'                     # 本机 SQL Server
DATABASE = 'AI'                  # 数据库名

def get_db_connection():
    conn_str = (
        f'DRIVER={{SQL Server Native Client 11.0}};'
        f'SERVER={SERVER};DATABASE={DATABASE};Trusted_Connection=yes;'
    )
    return pyodbc.connect(conn_str)
```

要点：

- 驱动名要用花括号包住，例如 `{SQL Server Native Client 11.0}` 或 `{ODBC Driver 17 for SQL Server}`；
- Windows 可信连接用 `Trusted_Connection=yes`；若用账号密码，则改为 `UID=...;PWD=...`；
- 每个请求自己获取/关闭连接，不使用全局共享连接。

## 4. 从一张表生成一套接口的总体流程

1. 确认表结构（字段名、类型、主键、外键）——见 `database.sql`；
2. 在 `schemas.py` 中为该表添加 3 个模型：`XxxCreate`（创建/更新入参）、`Xxx`（实体出参）、`XxxList`（分页列表出参）；
3. 新建 `xxxApi.py`，按第 5 节的模板实现 `register_xxx_routes(app)`，在内部用装饰器注册全部路由；
4. 在 `main.py` 中 `from xxxApi import register_xxx_routes` 并调用 `register_xxx_routes(app)`；
5. 启动服务，打开 `/docs` 或 `/openapi.json` 验证路由已注册。

## 5. 接口模板（以表 `FloorInfo` 为例）

假设表结构为：

```sql
CREATE TABLE FloorInfo (
    floorId          INT PRIMARY KEY IDENTITY(1,1), -- 楼层Id
    floorName        NVARCHAR(200),                 -- 楼层名称
    buildingId       INT,                           -- 所属建筑Id
    floorDescription NVARCHAR(200)                  -- 楼层描述
);
```

### 5.1 Pydantic 模型（schemas.py）

```python
class FloorCreate(BaseModel):
    """创建楼层请求模型"""
    floorName: Optional[str] = Field(None, description="楼层名称")
    buildingId: Optional[int] = Field(None, description="所属建筑ID")
    floorDescription: Optional[str] = Field(None, description="楼层描述")

class Floor(BaseModel):
    """楼层响应模型"""
    floorId: int
    floorName: Optional[str] = None
    buildingId: Optional[int] = None
    floorDescription: Optional[str] = None

    class Config:
        from_attributes = True

class FloorList(BaseModel):
    """楼层列表响应"""
    total: int
    rows: List[Floor]
```

字段一律与数据库列一一对应；`Create` 模型可全字段可空，便于前端按需传值。

### 5.2 新增（POST）

```python
@app.post("/api/floors", response_model=Floor, status_code=201)
def create_floor(floor: FloorCreate):
    connection = None
    cursor = None
    try:
        connection = get_db_connection()
        cursor = connection.cursor()
        cursor.execute(
            "INSERT INTO FloorInfo (floorName, buildingId, floorDescription) VALUES (?, ?, ?)",
            (floor.floorName, floor.buildingId, floor.floorDescription),
        )
        connection.commit()
        # 返回刚插入的记录
        cursor.execute(
            "SELECT TOP 1 floorId, floorName, buildingId, floorDescription "
            "FROM FloorInfo ORDER BY floorId DESC"
        )
        row = cursor.fetchone()
        ...
    except Exception as e:
        if connection:
            connection.rollback()
        raise HTTPException(status_code=500, detail=f"创建失败: {str(e)}")
    finally:
        if cursor:
            cursor.close()
        if connection:
            connection.close()
```

规范：全部 SQL 使用 **`?` 参数化占位**，禁止把用户输入直接拼进 SQL（防注入）。

### 5.3 更新（PUT）

- 先 `SELECT COUNT(*) ... WHERE 主键 = ?` 判断记录是否存在，不存在返回 404；
- 再执行 `UPDATE ... SET 字段 = ? WHERE 主键 = ?`；
- `commit()` 后重新查询该记录并返回，保证出参与实体一致。

### 5.4 删除

- 单个删除：`DELETE /api/floors/{floor_id}`，先查存在性（不存在 404），再删除；
- 批量删除：`DELETE /api/floorsDelete?floor_ids=1&floor_ids=2`，用 `IN (?, ?, ...)` 动态占位，先比对存在数量，再统一删除，返回 `{"msg", "status", "deleted_count"}`。

### 5.5 分页列表（GET）

推荐使用 SQL Server 的 `ROW_NUMBER()` 分页，一条 SQL 同时支持排序、筛选与分页：

```sql
SELECT * FROM (
    SELECT ROW_NUMBER() OVER (ORDER BY floorId ASC) AS RowNum,
           floorId, floorName, buildingId, floorDescription
    FROM FloorInfo
    WHERE 1 = 1                    -- 条件按需追加
) AS RankedFloors
WHERE RowNum BETWEEN ? AND ?
```

实现要点：

- `start_row = (page - 1) * rows + 1`，`end_row = page * rows`；
- 先执行 `SELECT COUNT(*)` 得到 `total`，再查当前页；
- 筛选条件使用「条件列表 + 参数列表」动态拼接，例如 `buildingId = ?`、`floorName LIKE ?`；
- `sort_by` 只接受白名单字段（如 `floorName`、`buildingId`）加 `asc/desc`，防止 SQL 注入。

### 5.6 模糊搜索（GET /search）

```python
@app.get("/api/floors/search")
def search_floors(keyword: str = Query(..., min_length=1)):
    ...
    pattern = f"%{keyword}%"
    cursor.execute(
        "SELECT TOP 20 ... FROM FloorInfo "
        "WHERE floorName LIKE ? OR floorDescription LIKE ? ORDER BY floorId",
        (pattern, pattern),
    )
```

返回结构统一为 `{"total": n, "keyword": keyword, "floors": [...]}`。

### 5.7 按外键查询（可选）

若表含外键（如 `buildingId`），可额外提供按外键过滤的接口：

- `GET /api/floors/building?buildingId=1&page=1&page_size=10`：查询某建筑下的全部楼层，同样分页返回。

## 6. 统一代码规范（务必遵守）

1. 每个模块只暴露一个 `register_xxx_routes(app: FastAPI)` 函数，路由用闭包内函数注册，不额外创建 APIRouter（保持与现有模块一致）；
2. 所有接口函数内部统一使用 `try / except / finally`：
   - `except Exception` 时 `rollback()` 并返回 `HTTPException(status_code=500, detail=...)`；
   - `finally` 中关闭 `cursor` 与 `connection`；
   - 查询类接口返回 `{"total": ..., "rows": [...]}`（列表）或实体对象（单条）；
3. 路径参数、查询参数尽量声明类型与 `Query(...)` 校验（`ge`、`le`、`min_length` 等）；
4. 字段命名与数据库列保持一致（本项目使用 `floorId`、`buildingId` 这类驼峰命名）；
5. 中文字段名（如 `乘车月份`）也可用于模型，但新建模块建议使用英文字段；
6. 字面量路由（如 `/api/floors/building`、`/api/floors/search`）必须注册在 `/api/floors/{floor_id}` 之前，避免被路径参数路由抢先匹配。

## 8. 常见问题

| 现象 | 原因与解决办法 |
| --- | --- |
| 控制台中文乱码 | 代码中把 `sys.stdout` 包装为 UTF-8：`sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')` |
| `'type' object is not subscriptable` | Python < 3.9 下使用 `list[...]`，应改用 `typing.List[...]` |
| `IM002 找不到驱动` | ODBC 驱动未安装，改连接串为已安装驱动名（如 `ODBC Driver 17 for SQL Server`） |
| `安全包中没有可用的凭证` | Windows 可信连接在无凭据的会话中失败；确认 SQL Server 已启动，或改用 SQL 账号密码认证 |
| 接口 500：表不存在 | 先在 SQL Server 中执行 `database.sql` 建表 |
| 删除被外键约束阻挡 | 存在子表引用（如 `FloorInfo` 被 `RoomInfo.floorId` 引用），需先处理子表数据或删除约束 |
| 分页数据重复/漏行 | 确保 `ROW_NUMBER() OVER (ORDER BY ...)` 排序字段唯一或稳定（推荐主键兜底） |

## 9. 新表生成 Checklist

拿到任何一张新表后，按下列清单逐项完成即可：

- [ ] 阅读建表脚本，列出字段、主键、外键；
- [ ] `schemas.py` 添加 `XxxCreate`、`Xxx`、`XxxList`；
- [ ] 新建 `xxxApi.py`，实现新增、修改、删除、批量删除、分页列表、搜索、按 ID 查询；
- [ ] 外键字段提供等值筛选或按外键查询接口；
- [ ] `main.py` 导入并注册路由；
- [ ] 启动服务，在 `/docs` 里对每个接口做冒烟测试。
